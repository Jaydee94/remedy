# Cycle 7c: the webhook source, implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any monitoring tool that can send an HTTP request can report an incident to Remedy: `POST /webhook/v1/{endpoint}` with a per-endpoint bearer token and a strict JSON body opens, updates or resolves an incident of the new source `webhook`, which the outage responder diagnoses like an alert.

**Architecture:** A third listener (`REMEDY_WEBHOOK_ADDR`, off by default) serves only the webhook route and `/healthz`. The handler in `internal/webhook` authenticates against `webhook_endpoints` (hashed tokens), applies per-endpoint limits in memory, decodes the body strictly, normalises it with the bounding helpers the Alertmanager source already uses (exported from `internal/signals`), maps a host from the labels and calls `incident.Engine.ObserveSignal`. A sweeper resolves webhook incidents that stay silent longer than the endpoint's `resolve_after`. The admin API `/api/webhooks` and a Setup block manage the endpoints. The responder, the prompt and the thread learn the source `webhook`.

**Tech Stack:** Go (`internal/store`, `internal/webhook`, `internal/signals`, `internal/incident`, `internal/responder`, `internal/prompt`, `internal/server`, `internal/config`, `internal/app`, `cmd/remedy-server`), React/TypeScript (`web/src`), Helm (`deploy/chart`), Markdown.

**Spec:** `docs/specs/2026-10-21-self-hosted-for-others-design.md`, section 6 (and 8, 9, 11, 13 where they touch the webhook). 7a and 7b are merged (release 0.20.0).

## Global Constraints

- Everything in the repo is English. The pull request of this cycle is `feat:` (a new source, nothing existing changes); the plan's own is `docs:`.
- **No route exists unless `REMEDY_WEBHOOK_ADDR` is set.** The webhook route is registered on the third mux only; the public and the internal mux never serve it (a test asserts 404 on both). The address must differ from `REMEDY_ADDR` and `REMEDY_INTERNAL_ADDR`.
- **The token is generated by Remedy** (32 random bytes, base64url, the way `MintRunToken` does it), shown once at creation or rotation, stored only as a SHA-256 hash (`hashToken`), compared in constant time, and accepted only as `Authorization: Bearer ...`, never in the URL. It never appears in a log, an error, an activity entry or an API answer after the response that created it.
- **An unknown endpoint, a disabled one and a wrong token answer the same `401` with the same body and do the same work** (a dummy compare for an unknown name). A failed request writes nothing to the database or to `activity`.
- **Everything the sender writes is untrusted text.** It is bounded and redacted by the same code as an alert (`signals.Bounded`, `OneLine`, `Cut`, `CleanURL`: one definition of "bounded alert text") and reaches an agent only through `internal/prompt`, in a data block.
- **No limit is per IP** (Remedy does not trust `X-Forwarded-For`). Limits are per endpoint: 60 requests per minute with a burst of 120 (`429` and `Retry-After`), at most 30 new incidents per hour (`429` for a new key only; updates and resolves are always accepted), at most 8 requests in flight on the listener (`503` beyond). Limits are columns of the endpoint where the spec says "limits" (`rate_per_minute`, `new_per_hour`); the burst is twice the rate; the in-flight cap is a constant.
- **Diagnosis is off by default per endpoint** (`auto_diagnose` false): a leaked token must not spend the operator's quota or money. The existing daily limits and, in key mode, the budget apply when it is on.
- **A touch or a rejection writes no activity entry.** Only what the engine writes (open, reopen, resolve) does, so a sender cannot grow the append-only table by repeating itself.
- The migration number is **004** (the spec's "018" is the SQLite numbering; `003_runs_auth_source.sql` is the last). Widening the `source` CHECK is `DROP CONSTRAINT` and `ADD CONSTRAINT` in PostgreSQL, not a table rebuild. Existing tests list the applied migrations in one constant, `appliedMigrations` in `internal/store/schema_test.go`; update it.
- Do not add a dependency. Tests: Go tests need PostgreSQL (`make test` starts one); chart tests need `helm`; `make check` is the authority before the pull request.

## Review Focus

1. **A request flood and a retry storm.** A sender that repeats every second keeps one incident alive and writes no activity; a flood of distinct keys stops at 30 new incidents per hour per endpoint while `resolved` bodies still get through; more than 8 requests in flight answer `503` without touching the database. (Tasks 6, 7.)
2. **Auth timing and sameness.** The three failure cases (unknown name, disabled endpoint, wrong token) must be byte-identical in status, headers and body; a request with no `Authorization` header, a `Basic` scheme or an oversized header is the same `401`. During the 24 h overlap after a rotation both tokens work, afterwards only the new one. (Task 5.)
3. **Hostile body.** A body of 64 KiB + 1 byte (`413`), a wrong `Content-Type` (`415`), an unknown or missing member, a nested object where a string belongs, control characters and invisible characters in `key` and `title`, a `key` that redaction would change, a 10 MB body sent slowly, and a second JSON value after the first. Nothing is stored for any of them. (Task 4, 7.)
4. **Prompt injection through a title, a label or an annotation** is data in a block and cannot close the block (`prompt` test with the delimiter inside the text); `Source:` in the prompt is a fact the control plane writes, not text from the sender. (Task 2.)
5. **Silence and return.** A sender that stops: the sweeper resolves after `resolve_after` with the reason `expired` and a thread sentence that says "not reported", not "fixed"; `resolve_after = 0` never resolves; a `firing` after a resolve reopens the incident and a diagnosed one is not diagnosed again on its own; a `resolved` for an unknown key is a `200` no-op. (Tasks 7, 8.)
