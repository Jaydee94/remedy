# The runner's login from the Setup page (K-7) Implementation Plan

Amended 2026-10-22: the switch of Tasks 3, 4, 5 and 7 was removed (see the spec, section 12)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The maintainer logs the runner's `claude` CLI in from a four-step wizard on the Setup page: the runner starts `claude auth login`, the page shows the sign-in link, the maintainer pastes the one-time code, the control plane hands it to the runner, and success is confirmed with `claude auth status`. Off by default, memory only, nothing of the material in any sink.

**Architecture:** A new stdlib-only package `internal/loginrelay` holds the rules (`Material`, `ValidateURL`, `ValidateCode`, the reason vocabulary, the strict wire decoders) and the session `Manager` (state machine, timers, rate limits, command queue with acks, claim gate). The server mounts four admin routes and two runner routes only when `Deps.Login` is set. The runner gets a fourth goroutine (`runner.LoginRelay`) that long-polls, owns the child process group and reports; `LoginChecker` learns to pause and to be kicked. The web gets two pure, `node --test`-tested modules and one component inside `RunnerSection`.

**Tech Stack:** Go (stdlib only, no new dependency), Helm templates and the Go render tests in `deploy/`, React 19 + TypeScript with `node --test` for pure logic, a POSIX-`sh` fake CLI, Playwright for the real-browser walk.

**Spec:** [`docs/specs/2026-10-21-ui-login-relay-design.md`](../specs/2026-10-21-ui-login-relay-design.md) (approved 2026-10-21; sections 6 to 9 and 13 carry the behaviour, 14 the order, 17 the documents). Parents: `docs/design.md` 2.7.1 (the exception, already recorded), `docs/research/k8s-s5-login-relay.md` (what was measured).

**Pull requests.** **A** `feat: log the runner in from the Setup page, server, runner and chart (K-7)`: Tasks 1 to 9, everything Go, chart and documents; the merge releases a feature that is off by default. **B** `feat: the login wizard on the Setup page (K-7)`: Tasks 10 and 11, the web, and the real-browser walk (needs A merged for the walk). **C** `docs: the real run of the runner login from the Setup page (K-7)`: Task 12, with the maintainer present; it costs one login.

**Parallelism** (subagent-driven). Wave 1, no dependencies between them: Task 1 (rules), Task 3 (command, fake CLI, switch), Task 7 (chart), Task 8 (backup prune), Task 10 (web pure modules; it builds against the JSON shapes of Task 4's Interfaces). Wave 2: Task 2 (needs 1), Task 5 (needs 1 and 3). Wave 3: Task 4 (needs 1, 2, 3). Wave 4: Task 6 (needs 4 and 5), Task 9 (documents, needs the final names). Task 11 needs A merged and Task 10; Task 12 needs everything and the maintainer. ## Global Constraints

- Everything in the repo is English. Go is stdlib-first; **no new dependency** (no PTY library: a PTY is the spec's fallback and needs an amended spec first). `gofmt -w` every Go file; a new file name must be free (`command ls <path>` first). `Store.inTx` bodies use only the `tx`. A migration is **not** needed (`activity.kind` has no CHECK).
- Test first for logic. Fake `claude` scripts are POSIX `sh` that run on macOS and Linux: `read -r`, `printf`, `trap`, `[ -f ]`, `cat`, `kill`; no `bash`-isms, no `stat -f`, `sed -i ''`, `date -j`. A test that needs an invisible or non-ASCII character builds it with a numeric rune literal or a token of the shared cases (`<NUL>`, `<CYR>`), never with a backslash-u escape in a source or fixture file (the Write tool turns it into the raw character); every Go task ends with `grep -nP '[^\x00-\x7F]' <its Go files>` (no hit allowed except an em dash in prose).
- **The material.** URL and code live only in `loginrelay.Material` (a `[]byte` holder answering `***` to every `fmt` verb, JSON and `slog`). Never in a database row, activity entry, log line, event, error, answer to a browser (the code is write-only; the URL only in `GET /api/runner/login` while `awaiting_code`), path, query or header. The relay never uses `runner.Execute`, never posts CLI output, never opens a file of the login directory (Task 8 lists names only). Errors and log fields are fixed words.
- Values from the spec: session TTL 10 minutes in any non-terminal state; `starting` 30 s without URL fails `no_url`; `submitting` 60 s without result fails `timeout`; `Manager` ticker 5 s; poll held up to 25 s (`204` or `200`); runner counts as online if a poll was seen in the last 45 s (`runnerGrace`); no poll and no report for 60 s fails `runner_lost`; 3 attempts, then `failed/invalid_code`; the last terminal session stays readable 10 minutes without URL or code, then `idle`; rate limit 5 starts per 10 minutes and 10 code submissions per session (`429` with `Retry-After`); code route body 1 KiB, report body 4 KiB, both strict (`DisallowUnknownFields`, nothing after the object); URL at most 2048 bytes; code 8 to 512 bytes of `0x21` to `0x7E` after trimming; child: `Setpgid`, SIGTERM to the group first, `WaitDelay` 3 s, a best-effort SIGKILL of the group after `Wait`, `main` waits up to 5 s for the relay goroutine; success path while `submitting`: `LoginCheck` every 2 s, the child gets 10 s to exit after `ok` (only when the login was missing before); a re-login counts only the exit code and a child alive after 60 s is `timeout`; backups: keep the 5 newest of `^\.claude\.json\.backup\.[0-9]{13}$` by the number in the name; the page polls every 2 s while a session is open, 10 s otherwise; activity kinds `login_started`, `login_succeeded`, `login_failed`, `login_cancelled`, `data` `{}` or `{"reason": "<word>"}`, no run id.
- **Reasons** (`failed`): `no_url`, `bad_url`, `invalid_code`, `process_exited`, `not_confirmed`, `timeout`, `runner_lost`, `runner_restarted`, `expired`, `cancelled`; plus `run_active` (the runner's belt-and-braces refusal, missing from the spec's list). A runner may report only `no_url`, `bad_url`, `invalid_code`, `process_exited`, `not_confirmed`, `timeout`, `run_active`. **Refusals** (`409` before a session exists): `disabled`, `runner_offline`, `run_active`, `already_active`, `api_key_mode`, plus `replace_required` (the spec demands the flag but names no word).
- Admin API: session cookie plus `X-Remedy-CSRF: 1` on every non-GET; runner API: the runner token. **Every answer of the four admin routes, errors and `401`/`403` included, carries `Cache-Control: no-store`.** Session ids are random 128-bit values in bodies only.
- UI: a button that starts a request keeps focus (`aria-disabled` plus a guard in the handler, not `disabled`); live region announces by key (`useAnnouncement`); focus moves to the step heading on a step change (`useFocusRestore`); the code field is cleared on submit, cancel and unmount and has no draft in `localStorage`/`sessionStorage`; `autocomplete="off"`, `spellcheck="false"`; modules in `web/src/*.ts` import relatively with `.ts` extensions; `import type`; no enums.
- Never run `go test -race ./internal/server` whole (about 25 minutes): use `-run`. A fresh worktree needs `make web-install`. `make check` is the authority; `make chart-check` needs `helm`.
- Commits are two plain commands (`git add <files by name>`, then `git commit -F <message file in the scratchpad>`), never `git add -A`; messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`, pull request bodies with the Claude Code line.

## Review Focus

The spec implies these; each has its test in the owning task.

1. **The code arriving twice** (a lost poll response, or the runner restarting between two polls): it must be written to the CLI once, and a restarted runner must never replay it. Task 2 (`TestACodeStaysPendingUntilAckedAndIsZeroedThen`), Task 5 (`TestACodeResentAfterALostResponseIsWrittenOnce`, `TestARestartedRunnerNeverReplaysACode`).
2. **A hostile `url` in the runner's report** (another host, a field with a state that carries none, a 5 KiB body): refused or failed `bad_url`, never stored, never shown, and the child killed. Tasks 1, 2, 4 (`TestAHostileReportedURLFailsTheSessionAndShowsNothing`) and 6.
3. **The login check flapping while the CLI rewrites its config**: the published state must not leave `missing` mid-session and must turn `ok` within seconds after success. Task 5 (`TestTheLoginCheckerIsPausedWhileASessionIsOpen`, `TestAnInFlightCheckIsDiscardedWhenASessionOpens`, `TestTheCheckerIsKickedWhenTheSessionEnds`).
4. **Two browser tabs on different steps**: the stale tab's code is refused with `409`, the second start with `already_active`, and the stale tab explains it instead of failing silently. Tasks 2 and 4 (`409`), Task 10 (`conflictSentence`), Task 11 (two tabs).
5. **A reload on step 3 with a half-typed code**: the page lands on step 2 with an empty field, nothing typed is in storage or the network log. Task 10 (`stepOf` with `typing` false), Task 11.

Modes: `valid-exits`, `valid-stays`, `invalid-stdout`, `invalid-stderr`, `no-url`, `bad-url`, `exit-early`, `lingering`, `ignores-term`. The script stores `URL` and `Code` in files of its `Dir` and reads them (no quoting); `auth login` prints `Opening browser to sign in`, U+2026 as `printf '\342\200\246\n'`, `If the browser didn't open, visit: <URL>` and `Paste code here if prompted > ` without a newline, appends its pid (and the background sleeper's for `lingering`) to the pid file, then `read -r line`, counting lines. `valid-*` accept only the planted code, any other line prints `Invalid code.
